# Processes

**Content type:** Requirements, guidance, and selectable profiles

This directory defines how WSP work is planned, performed, measured, reviewed,
and improved.

## Contents

- [Personal Software Process alignment](personal-software-process-alignment.md)
  explains where WSP uses concepts from the Personal Software Process (PSP).
- [Personal process](personal-process.md) defines the selectable
  `WSP-PSP-####` requirements for disciplined individual software work.

## Scope

PSP applies primarily to the work of an individual engineer. WSP uses PSP where
personal estimates, time and defect data, reviews, quality planning, and
postmortem improvement can improve project outcomes.

Project-wide decisions remain governed by WSP architecture, requirements,
testing, release, and documentation processes. ISO/IEC/IEEE 29119 remains the
primary WSP reference for software-testing processes and documentation.

## Adoption

A project may select the personal-process profile in its WSP adoption record.
When selected, the project shall define:

- the work types and contributors in scope;
- the planning and measurement records to retain;
- the approved tools or forms;
- how personal data is protected and aggregated; and
- how improvement proposals enter the project change process.

Personal measures shall be used to help engineers plan and improve their work.
They shall not be used as isolated performance rankings or compared without
context, consent, and appropriate governance.
