# Information for Users

**Content type:** Requirements and standards guidance

This directory defines the selectable WSP information-for-users profile for
projects that supply a user manual, quick start, online or embedded help,
command reference, tutorial, administrator guide, API information, or another
information product used to operate or support software.

The profile uses *information for users* as the umbrella term. A project does
not have to publish one monolithic manual, and splitting the information among
several media does not remove any applicable content or quality obligation.

- [Information-for-users requirements](requirements.md) define WSP-owned,
  verifiable planning, content, quality, release, and maintenance obligations.
- [Standards alignment](standards-alignment.md) explains their relationship to
  ISO/IEC/IEEE 26514:2022 without reproducing controlled standards text or
  implying conformity.

## Adoption

A project should select this profile when people need supplier-provided
information to install, configure, operate, administer, update, recover, or
integrate its software. This includes command-line and API users. A component
that supplies no information directly to users can record the profile as not
selected only when another controlled product or service owns all applicable
user information.

The adopting project dispositions every requirement and completes a
project-owned [information plan and acceptance record](../templates/user-information-plan-template.md).
Existing controlled artifacts can satisfy that template when they provide the
same identified content and traceability.

## Expected Project Evidence

The profile expects evidence proportional to the information set, including:

- the supported product baseline and inventory of information products;
- audience, task, and information-needs analyses;
- traceable information requirements and a controlled information architecture;
- reviewed drafts and results from representative information-use tasks;
- technical, editorial, accessibility, link, and example-validation results;
- an approved release acceptance record for the exact software and information
  versions; and
- controlled feedback, maintenance, and change records.

The profile complements the [UX/UI profile](../ux/README.md). Embedded help and
the interaction used to find or consume information are in both scopes when
both profiles are selected.
